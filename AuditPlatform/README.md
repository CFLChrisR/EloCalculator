# 3PL Audit Platform

The auditing side of the 3PL audit system. Intake normalizes documents into an **audit package**
([contract](docs/intake-contract.md)); this platform audits it automatically, drafts disputes for
high-confidence findings, queues the rest for review, and keeps a **reference library** of
regulations and best practices by jurisdiction, each linked to a source you can check.

Built standalone so it can move to its own repository: everything lives under `AuditPlatform/`.

## What it audits

| Module | Rules |
|---|---|
| **3PL invoice vs contract** | Rate above contract, uncontracted charges, extension errors (with line minimums), invoice total ≠ lines, billed quantity > client activity, duplicate charges (by reference or by period), missing required approvals, over-applied monthly minimums, billing outside the contract term |
| **Freight bills** (LTL, parcel) | Duplicate PRO, base vs lane rate (most specific lane wins, discount + minimum), fuel vs contract table at ship-week diesel, unrequested/uncontracted/over-cap accessorials, billed vs actual weight, parcel dimensional weight, class vs density class, late guaranteed delivery (refunds the whole bill and replaces the other checks) |
| **Retailer deductions** | Shortage vs clean POD, partial shortage vs POD exception, late/early ship vs ship window, ASN timing vs retailer deadline, labeling vs compliance record, duplicates, missing evidence |
| **Warehouse compliance** | Missing, expired or expiring credentials, and missing or stale training. **Driven by the library**: any entry with a `requirement` is enforced for facilities in its jurisdiction, so adding a state rule in the UI makes it part of the audit. |

`GET /api/rules` lists every rule id with a description.

### Auditing without manual review

Each finding has a **confidence** and a **recoverable amount**. The engine assigns a disposition:

- **AutoDispute**: confidence ≥ 90% and ≥ $25 recoverable (both configurable). A dispute letter is drafted and the finding is marked *Disputed*.
- **NeedsReview**: lower confidence, a passed deadline, or any compliance finding.
- **Informational**: too small to pursue.

Deadlines are calculated per finding: 180 days from bill receipt for motor carriers
(49 U.S.C. § 13710(a)(3)), a configurable parcel claim window, and retailer dispute windows from
each retailer profile. Re-running an audit keeps earlier review decisions, because finding ids are
stable.

Thresholds and tolerances live in `appsettings.json` → `Audit` (see `AuditSettings.cs`), including
the LTL density table.

## Reference library

`data/regulations/*.json` seeds the library (copied into the database on first start; seeding never
overwrites your edits):

- **Federal (US)**: freight claims and billing disputes (49 U.S.C. §§ 13710, 14705, 14706; 49 CFR 370), OSHA warehouse rules (1910.176, .178, .157; Part 1904; State Plans), hazmat training (49 CFR 172.704), FDA food facility registration, sanitary transportation and storage (21 CFR 1, 117), DSCSA 3PL licensing, DEA registration, EIA diesel index.
- **Model codes & industry standards**: UCC Article 7 (§§ 7-202, 7-204, 7-209), NMFC density, GS1 logistic label, X12 856, 3PL billing controls.
- **Every state + DC**: that state's UCC Article 7 enactment, and whether OSHA or a state plan covers private warehouses there (generated by `tools/generate_state_seed.py`).

### Verifiable sources

Each entry has a source URL (official sources preferred: eCFR, the U.S. Code, agency sites, state
legislature code sites), an **expected phrase**, and a verification record:

| Status | Meaning |
|---|---|
| `Unverified` | Never checked. Every seeded entry starts here. |
| `NeedsSource` | No URL yet. For example, states where the official code link still needs finding. |
| `SourceMatched` | The page loaded and contains the expected phrase (automated check). |
| `PhraseMissing` / `Broken` | The page changed or failed to load. |
| `HumanVerified` | A person read the source and recorded who, when, and the passage relied on. |
| `ChangedSinceVerified` | Was human-verified, but the expected phrase has since disappeared from the page. |

Only `SourceMatched` and `HumanVerified` citations appear in dispute letters; anything else is
listed as a warning to clear first. Compliance findings that rest on an unverified entry say so
and carry lower confidence.

**The seeded citations come from general knowledge and have not been checked against live
sources yet.** Run the check from a machine with internet access, then confirm the ones you rely on:

```bash
dotnet run --project src/ThreePLAudit.Cli -- verify-sources
```

```bash
dotnet run --project src/ThreePLAudit.Cli -- confirm US-49USC13710 --by "Your Name" --excerpt "within 180 days"
```

The same actions are buttons in the UI (**Check source**, **Confirm**, **Check sources**), and the
**Coverage** tab shows which state/topic cells are empty, so you can see where to research next
(state sales tax on warehousing services and state warehouse licensing start empty).

## Run it

Requires the .NET 10 SDK.

```bash
dotnet test
```

```bash
dotnet run --project src/ThreePLAudit.Api
```

Then open the URL it prints and upload `samples/sample-package.json`. It uses SQLite (`audit.db`) by
default. For SQL Server, set `Database:Provider` to `SqlServer` and `ConnectionStrings:Audit`
(see `appsettings.SqlServer.json`). The schema is created on start with `EnsureCreated`; switch to
EF migrations before production.

Command line, no server needed:

```bash
dotnet run --project src/ThreePLAudit.Cli -- audit samples/sample-package.json --csv findings.csv --disputes letters
```

```bash
dotnet run --project src/ThreePLAudit.Cli -- regs --state TX --topic warehouse-receipts-liens
```

## Layout

```
src/ThreePLAudit.Core   intake contract, rules engine, dispute drafter, reference library, source verifier
src/ThreePLAudit.Data   EF Core store (SQL Server / SQLite): packages, runs, findings + review state, library, check history
src/ThreePLAudit.Api    minimal API + web UI (wwwroot)
src/ThreePLAudit.Cli    threepl-audit: batch audits, library search, source verification
tests/                  xUnit tests covering every rule, the library, the verifier and the store
data/regulations        seed library (JSON)
samples                 example intake package that triggers every rule family
```

This tool supports audit work. It is not legal advice: confirm citations against the official
source, and have counsel review positions before relying on them in a dispute.
